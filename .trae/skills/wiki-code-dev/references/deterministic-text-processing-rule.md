# 确定性文本处理规则（Unicode / 去重 / 压缩 / 淘汰）

**代码**：CODING-DETERMINISTIC-TEXT
**严重级别**：critical

## 问题（Problem）

我们在"上下文记忆治理"模块踩了两类确定性错误：

1. **错误 Unicode 字符类**：正则 `CJK_RE = /[㐀-鿿豈-﫿　-〿＀-￯]/` 一并匹配了全角标点（。！），导致分词 / Jaccard 相似度去重算出**错误**的相似度，静默漏掉真正的重复条目。
2. **过度激进的清理破坏连贯性**：
   - 去重把"概念0"与"概念1"这类**模板相同但实体不同**的内容判为重复；
   - 低价值清理用"硬性最小长度"砍掉了虽短但有意义的问题（"甲"、"旧历史"）；
   - 淘汰（eviction）超出了受保护的近期窗口，删掉了应保留的上下文。

## 规则（Rule）

### R-1：分词使用精确码点区间，排除标点/符号块
只匹配 **CJK 表意文字 U+3400–U+9FFF + 扩展 A/B**，并**显式排除**全角标点（。！、`＀-￯` 等）与符号块。优先使用 `\p{Script=Han}`（引擎支持时）或精确范围，不要用一个大而全的连续区间把标点也包进去。

### R-2：token 估算采用固定比例
- CJK ≈ 1 token / 字符（`text.cjk_token_ratio: 1`）
- Latin ≈ 4 字符 / token（`text.latin_chars_per_token: 4`）

用于容量预算与压缩收益估算，避免混合文本上误判。

### R-3：去重必须"实体感知"
相似判定 = `Jaccard ≥ 阈值` **且** 不存在显著实体差异：
- 数字差异（"概念0" vs "概念1"）；
- 存在不同的 `[[wikilink]]` / `[[ref]]` 引用。
满足相似但实体不同 → 不算重复。

### R-4：低价值判定只看"空 / 纯标点 / 问候黑名单"
低价值 = 空内容、纯标点符号、命中问候黑名单（如"你好）**这三类 ONLY**。绝不可仅凭"短"就判定低价值——短问题（"甲"、"旧历史"）是有意义的。

### R-5：压缩预算保证净减少
保留长度 = `max(floor(len * compression.ratio), compression.min_floor_chars)`（`ratio=0.3`，`min_floor=40`）。该公式保证对足够长的文本产生**净 token 减少**，同时给短文本一个最小地板，避免把有意义短内容压没。

### R-6：淘汰保留连贯性地板
淘汰受保护的近期窗口 = `min(recencyWindow, eviction.coherence_floor_k)`（默认 4），**绝不**把受保护消息数压缩到该地板以下。

## 适用 / 不适用

- **适用**：记忆/上下文治理、分词、去重、压缩、淘汰、相似度计算、token 预算。
- **不适用**：不涉及文本语义处理的纯数值/IO 逻辑。

## 检查清单
- [ ] 分词正则是否排除了标点/符号块（只匹配 CJK 表意文字）
- [ ] token 估算是否用 1 CJK / 4 Latin 比例
- [ ] 去重是否同时检测实体差异（数字 / `[[ref]]`）
- [ ] 低价值是否仅基于空/纯标点/问候，而非长度
- [ ] 压缩是否用 `max(floor(len*0.3), 40)` 保证净减少
- [ ] 淘汰是否保护 `min(recencyWindow, 4)` 条近期消息
