## 三、规则定义详解

### CODING-056：外部 API 集成契约

- **场景**：调用第三方/外部 API（如 Agnes Image/Video API、OpenAI 兼容接口等）
- **规则**：
  1. 必须用 fetchWithDiagnostics 包装原生 fetch，按 `err.cause.code` 分类翻译为可读诊断信息（网络超时/DNS 失败/连接拒绝/证书错误）
  2. 响应字段必须做双重路径兼容（`data.url || data.metadata?.url`），应对外部 API 字段路径变更
  3. 调用方后端语言要求的字段类型必须显式转换（如 Go 后端 string 类型用 `String(value)`）
  4. fetchWithDiagnostics 必须 export，便于单元测试直接验证错误转换逻辑
- **参数化**：`external_api.diagnostic_error_codes`（错误码 → 提示文案映射表）

### CODING-057：超时分级策略

- **场景**：调用外部 API 或长任务时设置 AbortSignal.timeout
- **规则**：按预估耗时分级设置 timeout，禁止所有调用用同一超时值
  - 任务创建：30s（应秒级返回）
  - 任务轮询：30s（轮询应秒级返回，代理场景兜底）
  - 图像生成：60s（10-30s 常见，60s 兜底）
  - 视频下载：120s（大文件下载）
  - LLM 单轮调用：按 tokenBudget 调整（4k→60s, 16k→180s）
- **参数化**：`external_api.timeout_tiers`（任务类型 → 超时毫秒数映射表）

### CODING-058：多源密钥解析

- **场景**：调用需要 API Key 的外部服务
- **规则**：密钥解析必须按"专用段 → 共享段 → 环境变量"三级回退
  1. 专用段：`config.<service>.apiKey`（如 `media.agnes.apiKey`）
  2. 共享段：`config.llm.apiKeys.<provider>`（如 `llm.apiKeys.agnes`）
  3. 环境变量：`process.env[config.<service>.apiKeyRef]`
  4. 全部缺失时抛错并提示三个配置位置
- **参数化**：`api_key_resolution.fallback_chain`（回退链路顺序数组）

### CODING-059：长/短任务架构分离

- **场景**：新增功能涉及异步任务（视频生成、批量处理等）
- **规则**：
  1. 秒级任务（≤30s）走 SSE 同步流，复用 query 通道
  2. 分钟级任务（>60s）走独立 JSON 端点 + 前端轮询，避免 SSE 超时
  3. 破坏性端点（触发 LLM/外部 API 成本）限流 ≤ `long_task.destructive_rate_limit`（默认 5/min）
  4. 高频轮询端点限流 = `long_task.poll_rate_limit`（默认 60/min，与前端 `poll_interval_ms` 匹配）
  5. 错误码区分：配置缺失返 400，外部 API 失败返 500（用 `message.includes('not configured')` 判定）
  6. 错误必须双日志通道：JSON 响应给前端 + `request.log.error` 写后端日志流
  7. 路由文件顶部必须有"设计要点"块注释，列出端点职责、限流策略、关键设计决策的"为什么"
- **参数化**：`long_task.sse_threshold_ms` / `long_task.destructive_rate_limit` / `long_task.poll_rate_limit` / `long_task.poll_interval_ms`

### CODING-060：媒体归档 Markdown frontmatter 标准化

- **场景**：LLM 生成产物（图像/PPT/视频/播客等）归档到 vault
- **规则**：
  1. 归档到 `vault/queries/` 目录（已有 WRITE_ALLOWED_DIRS 白名单）
  2. frontmatter 必须含 `type: query` + `output_mode: <image|ppt|video|podcast>` + `generated_at: ISO8601`
  3. 业务字段（如 `image_file` / `video_file` / `task_id` / `source_url`）放同 frontmatter
  4. 文件名格式 `<output_mode>-YYYYMMDD-HHmmss.<ext>`（与 podcast-workflow 一致，排序友好）
  5. Marp 类归档文件 frontmatter 可合并 marp 字段（`marp: true` + 归档字段），避免双重 frontmatter
- **参数化**：`media_archive.frontmatter_required_fields` / `media_archive.filename_pattern` / `media_archive.archive_dir`

### CODING-061：会话存储双层淘汰 + 防篡改

- **场景**：内存 Map 存储会话/缓存数据
- **规则**：
  1. 内存 Map 必须双层淘汰：先按 TTL 淘汰过期，仍超限按插入顺序（Map.keys().next()）淘汰最早
  2. 上限 `session_store.max_sessions`（默认 100），TTL `session_store.ttl_ms`（默认 1 小时）
  3. 归档/查询类接口不接收客户端传内容，只接收引用（sessionId + messageIndex），内容从服务端 sessions 取
  4. 防止客户端篡改答案内容、伪造引用
- **参数化**：`session_store.max_sessions` / `session_store.ttl_ms` / `session_store.trust_client_content`（默认 false）

### CODING-062：prompt 单点存储

- **场景**：LLM prompt 模板管理
- **规则**：
  1. 所有 LLM prompt 模板存放在 `prompts/*.md` 单一目录
  2. 运行时按需 `fs.readFile` 加载，禁止在源码中内联 prompt 字符串
  3. 多个工作流（query/multimodal/podcast/media）共用同一目录
  4. 修改 prompt 不需重新编译，热加载生效
- **参数化**：`prompt_store.directory` / `prompt_store.file_pattern`

### CODING-063：SSE 事件对象映射分发

- **场景**：SSE 后端事件分发 + 前端事件消费
- **规则**：
  1. 后端按 chunk 字段独立 if 分发事件（`if (chunk.image) send('image', chunk.image)`），新增事件类型只需追加 if 分支
  2. 前端 SSE 事件处理器用对象映射表 `Record<string, Handler>` 替代 if/else 链（控制 SonarQube S3776 认知复杂度 < 15）
  3. outputMode 用 TypeScript 联合字面量类型（`'normal' | 'mindmap' | 'image' | 'ppt'`），新增模式追加字面量不破坏旧客户端
  4. outputMode（结构模式）与 outputModes（事件可见性）正交分离，不可混用
  5. 未知事件类型的默认 handler 行为必须明确（如 `console.warn`），禁止静默吞掉
- **参数化**：`sse_event.object_dispatch_threshold`（≥3 个事件类型必须用对象映射）

### CODING-064：SSE 流消费错误处理

- **场景**：前端 SSE 流消费函数
- **规则**：
  1. SSE 流消费函数必须吞掉 AbortError（`err.name === 'AbortError'` 直接 return），让调用方在 finally 处理停止态
  2. 调用方需区分"用户主动停止"和"真实错误"，避免主动取消污染 errorMessage 状态
  3. finally 中再次 `reader.cancel()` 兜底释放，吞掉已释放异常
  4. 流消费函数的 signal 参数必须可空，未传 signal 时不影响正常消费
- **参数化**：无（行为规则，无参数）

### CODING-065：长任务轮询 UI 模式

- **场景**：前端长任务（视频生成、批量处理等）UI 交互
- **规则**：
  1. 长任务用 `setInterval(poll_interval_ms)` 轮询，5 状态机驱动 UI 模板切换（`idle | queued | processing | completed | failed`）
  2. 轮询单次失败不终止，仅更新 error 文案，容忍网络抖动
  3. 完成/失败显式 `stopXxxPolling()` 停止定时器
  4. 用户停止/超时/正常完成三态用 `abortReason: 'user' | 'timeout' | null` 区分
  5. 超时用 `setTimeout` 而非 `AbortSignal.timeout`（因需同步设 abortReason 标记）
  6. "关闭对话框"（停轮询 + 关对话框 + 重置全部）与"重置状态保持对话框"（停轮询 + 清状态，允许重新生成）拆为两个函数
  7. onBeforeUnmount 必须清理 abortController + 所有 addEventListener + setInterval timer
- **参数化**：`long_task.poll_interval_ms` / `long_task.state_machine_values` / `long_task.timeout_ms`

### CODING-066：事件委托 + 生命周期清理

- **场景**：Vue 3 中 v-html 渲染内容的事件绑定 + 组件卸载清理
- **规则**：
  1. v-html 渲染的 DOM 无法绑定 Vue 事件，统一用父容器 `addEventListener` 事件委托
  2. 按 `target.tagName` / `target.closest(selector)` 命中目标元素
  3. onBeforeUnmount 必须移除所有 `addEventListener` 注册的监听器（函数引用需保存）
  4. 全局事件（`globalThis.addEventListener`）必须配对 `globalThis.removeEventListener`
  5. 第三方库实例（mermaid/marp）必须在 onBeforeUnmount 调用其 destroy/dispose 方法（若存在）
- **参数化**：无（行为规则）

### CODING-067：第三方重库动态加载

- **场景**：前端引入体积大的第三方库（mermaid ~600KB / marpit / monaco 等）
- **规则**：
  1. 体积大的库必须动态 `import()` 加载，避免首屏 bundle 膨胀
  2. 模块级 `xxxLoaded` 标志避免重复加载
  3. 实例（如 marpInstance）缓存复用，避免重建
  4. CJS 模块经 Vite 预构建后命名导出位置不确定，统一用 `mod.X ?? mod.default?.X` 兼容访问，缺失时显式抛错
  5. 第三方库错误行为不可控时（如 mermaid 11.x 错误 SVG 注入）用多层防护兜底：
     - 第一层：库选项抑制（如 `suppressErrorRendering: true`）
     - 第二层：渲染前 `parse()` 预解析验证
     - 第三层：渲染后清空容器再注入
     - 第四层：catch 中清空容器避免残留
     - 第五层：CSS 全局隐藏库内置错误元素（`.error-icon / .error-text { display: none !important }`）
  6. 渲染失败时降级显示原始内容（`<pre>{{ raw }}</pre>`），让用户排查 LLM 输出
  7. 动态 import + watch 回调中必须 `await nextTick()` 等 DOM 更新后容器 ref 才可用
- **参数化**：`heavy_library.dynamic_import_threshold_kb`（默认 200KB 以上需动态加载）/ `heavy_library.error_suppress_selectors`
